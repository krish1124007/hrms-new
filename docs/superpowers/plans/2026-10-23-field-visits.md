# Field Visits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the field-*sales* module with a field-*visits* module. Field employees pin sites, check in and out with GPS (and a selfie by default), work offline, file a work report with photos, documents, people met and checklists, and claim travel allowance by km. Managers plan visits, see the team's status and routes, and get reports — on the website and in the Android app.

**Architecture:** Three backend tasks: (1) a foundation that deletes sales, introduces `FieldSite`, field settings, permissions and the Google Maps service; then in parallel (2) the visit engine and (3) team/route/travel/reports. Two web tasks and two mobile tasks run in parallel with the backend against the HTTP contract fixed in this plan. One integration task merges, reviews, fixes, builds and deploys. The backend stays Express 5 + Mongoose 8 (no transactions: conditional writes, idempotency by client reference).

**Tech Stack:** Backend Node 22, Express 5 ESM, Mongoose 8, BullMQ, zod, vitest/supertest/mongodb-memory-server, `xlsx` and `pdfkit` (already installed), Google Routes API + Geocoding API over HTTPS (no SDK). Web React 19 + Vite 6 + TanStack Query + Leaflet/OSM. Mobile bare React Native 0.76.9 (new architecture) in the nested repo `dhrms-iosfinal/`, `react-native-maps` (Google provider, Android), MMKV, jest.

**Spec:** `docs/superpowers/specs/2026-10-23-field-visits-scope.md` (sections 4 and 8 are binding; section 8 overrides section 4).

## Global Constraints

- Sales is **deleted**: no `Product`, `ProductOrder`, `PaymentCollection`, `SalesTarget`, ledger, receipt PDF, order/receipt numbering, leaderboard, cart, or "sales" wording anywhere (backend, web, mobile). Order/payment links on visits go too.
- Names: module **Field Visits**; places are **Sites** (`FieldSite`, collection `fieldsites`); visits reference `siteId`; tasks reference `siteId`. Permissions **`field.view`** (own + direct reports) and **`field.manage`** (everyone + admin/settings). The old `field-sales.*` names are migrated, never just stripped.
- Tracking: **only at check-in/check-out points** (day attendance in/out and visit in/out). No periodic location upload from the app; `POST /field/tracking/batch` and the legacy attendance batch URL answer 200 `{ ignored: true }`.
- Offline: every mobile write that can happen at a site carries `clientRef` (UUID v4, idempotency) and `capturedAt` (device time, ISO). The server honours `capturedAt` when it is not in the future (2 min slack) and not older than `offlineMaxAgeDays` (setting, default 7); it stores `receivedAt` and sets `syncedLate = receivedAt − capturedAt > 15 min`.
- Business day and times: `backend/src/lib/business-day.ts` (IST) everywhere; web `src/lib/format.ts`; mobile `src/lib/ist.ts`.
- Google: backend env `GOOGLE_MAPS_API_KEY` (server key: Routes + Geocoding). Unset → no Google calls: addresses stay as entered, km uses the straight-line fallback. Mobile key from `android/local.properties` (`GOOGLE_MAPS_API_KEY=`, git-ignored) → manifest placeholder; `app.json` `"mapsEnabled": false` hides map views (list fallback) until the key is supplied. Never commit a key.
- Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; stage by path; never push; never commit `backend/.env`; no `dist` rebuilds before Task 8; production is read-only until Task 8.
- Tests: backend `npm run type-check && npm run lint && npx vitest run`; web `npm run type-check && npm run lint && npx vitest run && npm run build`; mobile `npm run type-check && npx jest`.

## Review Focus

1. Offline replay: the same check-in/check-out/report/pin sent twice (retry after a timeout) creates one record; a check-out captured before its check-in's sync arrives is applied in order (Tasks 2, 6).
2. A visit captured offline 3 days ago syncs today: it lands on the right business day, counts as that day's attendance when the employee had none, and is flagged `syncedLate` (Tasks 2, 6).
3. Travel allowance: one claim per employee per day; km = sum of legs between that day's ordered points; same-site check-in→check-out legs under 50 m ignored; Google failure falls back and marks `estimated` (Task 3).
4. A field employee without a manager, and an admin without an employee record, both get clear behaviour on My day, sites and the team map (no silent empty lists, no 500) (Tasks 1–7).
5. Deleting sales leaves no dangling route, import, navigation entry, permission name or test (Tasks 1, 4, 7, 8).

## HTTP contract (all under `/api/v1/field`, envelope `{ success, data, pagination? }`)

Permission legend: **V** = `field.view` (sees self + direct reports), **M** = `field.manage` (sees all). Writes on someone else's record need M or being their direct manager unless stated.

**Settings**
- `GET /settings` (V) → `FieldSettings`; `PUT /settings` (M).
- `FieldSettings = { selfieRequired: boolean (true), defaultSiteRadiusM: number (200), siteTypes: string[] (["Client office","Project site","Branch","Vendor","Government office","Other"]), visitPurposes: string[] (["Meeting","Inspection","Audit","Survey","Installation","Maintenance","Training","Other"]), shortVisitMinutes: number (5), autoCloseTime: "HH:mm" ("23:30"), offlineMaxAgeDays: number (7), visitCountsAsAttendance: boolean (true), vehicles: [{ type: "bike"|"car"|"other", label: string, ratePerKm: number }] ([{bike,"Two-wheeler",0},{car,"Car",0}]), checklists: [{ _id, name, purpose: string, items: [{ _id, label, kind: "yes_no"|"text"|"number"|"select"|"photo", options?: string[], required: boolean }] }] ([]) }`.

**Sites**
- `GET /sites?search&type&assignedTo&near=lat,lng&radiusKm&page&limit` (V: own-assigned, created-by-me and team; M: all) → `Site[]`.
- `GET /sites/map?bbox=minLng,minLat,maxLng,maxLat` (V) → `[{ _id, name, type, location, radiusM, lastVisitAt }]` (≤ 500).
- `GET /sites/:id` (V) → `Site & { recentVisits: VisitSummary[] }`.
- `POST /sites` (V — any field employee may pin) body `{ clientRef, capturedAt?, name, type, location: {lat,lng,accuracy?}, radiusM?, address?: Address, contactName?, contactPhone?, notes?, photo?: string /*upload key*/, assignedTo?: string[] }` → `Site`; creator is assigned; `createdVia: "mobile_pin"|"web"`; address reverse-geocoded when absent and Google configured. Idempotent by `clientRef`.
- `PATCH /sites/:id` (creator within 24 h, or M) · `DELETE /sites/:id` (M, soft).
- `POST /sites/import` (M) multipart `file` (.xlsx: Name, Type, Address, City, State, Pincode, Latitude, Longitude, Radius, Contact name, Contact phone, Assigned employee IDs) → `{ created, updated, errors: [{ row, message }] }`.
- `Site = { _id, name, type, address: { line1, city, state, pincode }, location: { lat, lng }, radiusM, contactName, contactPhone, notes, photoUrl?, assignedTo: [{ _id, firstName, lastName, employeeId }], createdBy: { _id, firstName, lastName }, createdVia, lastVisitAt?, visitCount, distanceM? }`.

**Uploads** — `POST /uploads/photo` (exists) and `POST /uploads/document` (pdf, images, doc/docx, xls/xlsx; ≤ 10 MB) → `{ url, key }` (signed URL + storage key; bodies send `key`).

**Visits**
- `Visit = { _id, clientRef, employee: {_id,firstName,lastName,employeeId}, site: {_id,name,type,location,radiusM}, purpose, status: "planned"|"in_progress"|"completed"|"cancelled"|"missed", plannedDate?, scheduleId?, checkIn?: { at, location?, accuracy?, selfieUrl?, distanceM? }, checkOut?: { at, location?, accuracy?, distanceM? }, durationMinutes?, flags: { awayFromSite, noGps, noSelfie, shortVisit, autoClosed, syncedLate, capturedOffline }, report?: Report, createdAt }`.
- `Report = { notes, photos: string[] /*urls*/, documents: [{ url, name }], peopleMet: [{ name, designation?, phone? }], outcome: "completed"|"follow_up"|"not_available"|"other", nextAction?, followUpDate?, checklist?: { checklistId, answers: [{ itemId, value }] }, submittedAt }`.
- `GET /visits?employeeId&siteId&status&from&to&page&limit` (V/M scope) · `GET /visits/:id`.
- `POST /visits/plan` (V for self and direct reports; M anyone) `{ siteId, employeeId?, plannedDate: "YYYY-MM-DD", purpose, notes? }` → `Visit(status planned)`; notifies the employee when planned by someone else.
- `POST /visits/check-in` (V, self) `{ clientRef, capturedAt?, visitId? /*planned*/, siteId? , newSite?: <POST /sites body without clientRef>, purpose, location?: {lat,lng,accuracy}, selfieKey?, notes? }` → `Visit(in_progress)`. Exactly one of `visitId`/`siteId`/`newSite`. 409 `VISIT_ALREADY_OPEN` when another visit is in progress for the employee at `capturedAt` (offline replays of an older day are allowed if that day's visit is closed). `selfieRequired && !selfieKey` → 400 `SELFIE_REQUIRED`. Flags computed from the site pin and radius. Attendance link (setting): when the employee has no attendance check-in on that business day, creates one at `capturedAt` (method `field_visit`, the visit's location).
- `POST /visits/:id/check-out` (V, own) `{ clientRef, capturedAt?, location?, report?: <Report without submittedAt; photos/documents as keys> }` → `Visit(completed)`; `durationMinutes`, `shortVisit` from settings. Checkout before check-in time → 400 `CHECKOUT_BEFORE_CHECKIN`.
- `PATCH /visits/:id/report` (owner within 48 h of check-out, or M) `{ clientRef, ...Report fields }` → `Visit`. Notifies the employee's reporting manager on first submission.
- `POST /visits/:id/cancel` (owner for planned/in_progress, or planner/M) `{ reason }`.
- `GET /my-day?date=YYYY-MM-DD` (V, self) → `{ date, inProgress: Visit|null, planned: Visit[], completed: Visit[], missed: Visit[], tasks: FieldTask[], attendance: { checkedInAt?, checkedOutAt? } }`.
- Schedules: `GET/POST /visit-schedules`, `PATCH/DELETE /visit-schedules/:id` (V for self/reports, M all) `{ siteId, employeeId, purpose, rule: { freq: "weekly"|"monthly", weekdays?: number[] /*1=Mon..7=Sun*/, dayOfMonth?: number, startDate, endDate? } }`. A nightly job (BullMQ, IST) creates planned visits 7 days ahead (idempotent per schedule+date) and marks yesterday's still-planned visits `missed`, and auto-closes visits still in progress from previous days at `autoCloseTime` (`flags.autoClosed`).

**Tasks at a site** — existing field-task endpoints keep their paths, with `siteId` replacing `clientId`; completion accepts `photoKeys: string[]`; assignee notified on create/reassign; manager notified on completion.

**Team, route, travel**
- `GET /team/status?date` (V/M scope) → `[{ employee, status: "at_site"|"between_sites"|"day_ended"|"not_started", currentVisit?: {_id, site:{_id,name}, since}, lastPoint?: { lat, lng, at, kind: "day_in"|"visit_in"|"visit_out"|"day_out", siteName? }, visitsToday: number, kmToday: number }]`.
- `GET /route/:employeeId?date` → `{ date, points: [{ lat, lng, at, kind, siteName? }], legs: [{ fromIndex, toIndex, distanceM, estimated }], totalKm, estimated }`.
- `GET /travel/day?date` (V, self) → `{ date, totalKm, estimated, legs, hasCompletedVisit, claim?: { _id, status, km, amount } }`.
- `POST /travel/claims` (V, self) `{ date, vehicleType, km?, reason? }` → `ExpenseClaim`. `km` omitted → computed km; when it differs from computed by > 5 %, `reason` is required (400 `REASON_REQUIRED`). 409 `TA_ALREADY_CLAIMED` (one per employee per date, unless the previous one was rejected); 400 `NO_FIELD_WORK` (no completed visit that day). Creates an `ExpenseClaim` in category **"Travel allowance"** (created if missing) with `amount = round(km × ratePerKm)`, `travel: { date, vehicleType, ratePerKm, computedKm, claimedKm, estimated, reason? }`, and it flows through normal expense approval.

**Reports** (V/M scope; `?format=xlsx|pdf` downloads a file, default JSON)
- `GET /reports/daily?employeeId&date` → timeline (visits with report summaries, legs, km).
- `GET /reports/summary?from&to&groupBy=employee|site|purpose` → `[{ key, label, visits, completed, missed, minutesOnSite, km }]`.
- `GET /reports/exceptions?from&to` → `[{ visitId, employee, site, date, type: "away_from_site"|"no_gps"|"no_selfie"|"short_visit"|"auto_closed"|"missed_plan"|"synced_late", detail }]`.
- `GET /reports/sites?from&to` → `[{ site, visits, lastVisitAt, employees }]`.
