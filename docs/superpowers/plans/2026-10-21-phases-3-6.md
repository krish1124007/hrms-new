## Global Constraints

- Modules in use: attendance, leave, payroll, expenses, **field visits + maps**. Projects/Timesheets/CRM/SaaS are out of scope: hide them from web and mobile navigation, do not extend them.
- Business dates: backend uses `backend/src/lib/business-day.ts` (`startOfBusinessDay`, `atBusinessTime`, `BUSINESS_TZ`, `DAY_MS`); web/mobile format and compute "today"/ranges in `Asia/Kolkata` through one helper per client; never `toISOString().slice(0,10)` on a local date.
- Permissions come only from `backend/src/config/permissions.ts`; the only new permission in this plan is `expenses.config` (Task 1). Field uses `field-sales.view` / `field-sales.manage`.
- Maps: Leaflet + OpenStreetMap tiles (no paid API key); tile URL configurable (`VITE_MAP_TILE_URL`, default OSM); marker icons bundled locally, never from a CDN.
- Push: Firebase Cloud Messaging through `firebase-admin`; configured by `FIREBASE_SERVICE_ACCOUNT_PATH` (path to the service-account JSON); unset → push is a silent no-op.
- Brand: product name **D-HRMS**, company **Dharmesh Deshani Group of Companies** (short **DDIPL**), support e-mail from `SUPPORT_EMAIL` env / `VITE_SUPPORT_EMAIL`; no "Tankar", "Fieldora", "DD HRMS", "opencore" in user-visible text (storage keys may keep `opencore.*`).
- English-only UI: remove the i18n machinery and its side effects; no language pickers.
- Commits: trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; stage by path; never push; never commit `backend/.env`; production is read-only. Do **not** rebuild or commit `backend/dist` / `frontend/dist` in Tasks 1–11 (Task 12 does it once).
- Tests: backend `cd backend && npm run type-check && npx vitest run`; web `cd frontend && npm run type-check && npx vitest run && npm run build`; mobile `cd dhrms-iosfinal && npm run type-check && npx jest` (after `npm ci`). A test that times out under machine load is rerun alone before it is investigated.

## Review Focus

1. Field order/receipt numbers after a record is soft-deleted and under concurrent creates — numbers keep increasing, never 409 (Task 3, test `numbering survives soft-delete and concurrency`).
2. Client outstanding after order/payment edit, cancel and delete equals Σ(confirmed + delivered order totals) − Σ(payments) (Task 3, test `ledger is recomputed after every mutation`).
3. "Today" between 00:00 and 05:30 IST on web lists/calendars, field dashboards and mobile history (Tasks 3, 6, 9 — each has an IST-midnight test).
4. A user without an employee profile (seeded admin) on self-service screens sees a clear "no employee profile" message, never a silent empty list or a raw 403 (Tasks 1, 6, 9).
5. Mobile session after a failed token refresh or logout: back on login with the query cache and stored tokens cleared, no previous user's data visible (Task 9, test `failed refresh clears session and cache`).

**Interfaces:**
- `nextSequence(key: string): Promise<number>` — atomic `findOneAndUpdate({ _id: key }, { $inc: { seq: 1 } }, { upsert: true, new: true })`; seeded on first use from the max existing number for that key (including soft-deleted docs). - `recomputeClientLedger(clientId): Promise<{ totalOrders, totalOrderValue, totalPayments, outstandingAmount }>` — from non-deleted orders with status `confirmed|delivered` and non-deleted payments; called after every order/payment create/update/status change/delete.
